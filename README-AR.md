# إيجاز — PHP وMySQL لخطة Hostinger Premium

## التشغيل

هذه نسخة خادم PHP بالكامل: تسجيل الدخول، الجلسات، قواعد الحفظ والمطابقة، رفع الملفات، تحديث البيانات والصور، النسخ السابقة، تنزيل الأصل والنسخ الاحتياطي. الواجهة نفسها وأدوات PDF وOCR والتعرف على الوجه تعمل بملفات JavaScript جاهزة داخل المتصفح. لا توجد حاجة إلى Node.js أو npm أو Composer أو سيرفر يعمل من جهازك بعد الرفع.

تم الحفاظ على رفع PDF وDOCX وDOC، الرفع المتعدد، الحفظ الفردي والجماعي، المراجعة، مطابقة الجوازات، السجلات، البحث والفلترة، تعديل البيانات والصور، النموذج العربي والإنجليزي، الطباعة وحفظ PDF من المتصفح، CSV، ونسخة SQL احتياطية تشمل الملفات والصور. الدول التسع كما هي، وأوغندا غير متاحة حاليًا مع دعم ملفاتها السابقة.

## الرفع على Hostinger Premium

1. افتح File Manager للموقع وارفع **محتويات الحزمة** داخل public_html. تأكد أن index.php وinstall.php ومجلدات assets وvendor وprivate وapi موجودة مباشرة في public_html، وأن الملف المخفي .htaccess رُفع أيضًا. يمكن استخدام مجلد فرعي إذا أردت.
2. من لوحة الموقع افتح PHP Configuration واختر PHP 8.3 أو أحدث. تأكد من تفعيل pdo_mysql. يفضّل تفعيل mbstring لدعم النصوص العربية؛ intl اختيارية. لا تحتاج إلى GD أو Tesseract أو Python أو أي أوامر تشغيل على السيرفر؛ OCR واكتشاف الوجه في المتصفح.
3. من Databases → Management أنشئ قاعدة MySQL ومستخدمًا وكلمة مرور. احتفظ بالاسمين الكاملين بما فيهما بادئة حساب Hostinger.
4. افتح https://your-domain/install.php. إذا رفعت في مجلد ejaz فالرابط https://your-domain/ejaz/install.php.
5. اكتب المضيف (عادة localhost أو القيمة الموضحة في لوحتك)، المنفذ 3306، اسم القاعدة والمستخدم وكلمة مرور القاعدة، ثم اختر اسم حساب المدير وكلمة مرور جديدة لا تقل عن 12 حرفًا وأكّدها.
6. اضغط «إنشاء الجداول وإكمال التثبيت». تُنشأ الجداول تلقائيًا دون حذف البيانات الموجودة، ويُنشأ private/config.php. تُقفل صفحة التثبيت بعد النجاح. سجّل الدخول بحساب المدير الذي اخترته.
7. جرّب نموذجًا مرفقًا، راجع البيانات واعتمدها ثم احفظها. افتح صفحة السجلات للتأكد من ظهور السيرة وصورتها وإمكانية تنزيل الأصل.

لا تختَر Node.js Web App لهذه النسخة، ولا تنفّذ npm install أو npm run dev. افتح رابط موقع PHP مباشرة بعد رفعه وإتمام التثبيت. لا تنشر مجلد node_modules أو ملفات النسخ السابقة مع هذه النسخة؛ فكها في مجلد جديد قبل الرفع.

راجع تفعيل HTTPS للموقع. قد تحتاج حدود الرفع التالية في PHP Options حسب خطة الاستضافة:

- upload_max_filesize: ‏26M أو أعلى.
- post_max_size: ‏32M أو أعلى.
- memory_limit: ‏256M أو أعلى.
- max_execution_time: ‏180.

ملف .user.ini يطلب هذه القيم، وتظل حدود خطة الاستضافة هي الحد الأعلى. حد التطبيق 25MB لكل سيرة، و10 ملفات في الدفعة، و20 صفحة للملف. عند الملفات الكبيرة يجب أن يسمح MySQL بحجم مناسب في max_allowed_packet أيضًا.

## مكان قاعدة البيانات والإعدادات

المثبت ينشئ الجداول من private/mysql-schema.sql. وتوجد نسخة يدوية داخل database/mysql-schema.sql لاستيرادها من phpMyAdmin عند الحاجة. لا يلزم الاستيراد اليدوي إذا استخدمت المثبت.

- registry: قائمة الجوازات المرجعية.
- records: البيانات الحالية للسير.
- history: النسخ السابقة.
- photos: الصور الشخصية كبايتات.
- uploaded_files: ملفات PDF وWord الأصلية كبايتات.
- login_attempts: عدادات مؤقتة لحماية تسجيل الدخول.

بيانات الاتصال محفوظة في private/config.php الذي ينشئه المثبت. كلمة مرور المدير محفوظة فيه كهاش، ولا توجد كلمة مرور افتراضية مزروعة. مجلد private محمي بواسطة .htaccess، والنماذج المرفقة لا تُتاح إلا بعد تسجيل الدخول. لا تغيّر owner_id بعد إدخال بياناتك إلا عند نقل ملكية السجلات بصورة مقصودة.

كل الملفات الجديدة محفوظة في MySQL؛ لا توجد حاجة إلى Cloudflare D1 أو R2 أو مجلد ملفات عام. من صفحة السجلات يمكن تنزيل SQL يشمل بيانات الحساب ونسخه السابقة وصوره والملفات الأصلية. يمكن كذلك أخذ نسخة كاملة من phpMyAdmin. لا تُستورد نسخة بيانات على قاعدة مأهولة دون نسخة احتياطية؛ معرّفات السجلات والجوازات فريدة.

## تشغيل محلي على XAMPP

1. فك الحزمة في مجلد جديد، مثل C:\xampp\htdocs\ejaz-php.
2. من XAMPP شغّل Apache وMySQL.
3. افتح http://localhost/phpmyadmin وأنشئ قاعدة فارغة بترميز utf8mb4.
4. افتح http://localhost/ejaz-php/install.php، واكتب بيانات MySQL المحلية. في XAMPP الافتراضي يكون المستخدم غالبًا root، وكلمة المرور فارغة إذا لم تُغيّرها. ضع القيمة الفعلية لإعداد جهازك.
5. اختر حساب المدير وأكمل التثبيت، ثم افتح http://localhost/ejaz-php/.

إذا ظهرت 404 لمسارات api أو records على Apache المحلي، تأكد من وجود .htaccess وتفعيل mod_rewrite والسماح بـAllowOverride لهذا المجلد. يستمر Apache وMySQL في العمل من لوحة XAMPP؛ لا تحتاج npm أو Node.js.

للمطورين الذين لديهم PHP CLI فقط، يمكن التشغيل المحلي اختياريًا بالأمر php -S 127.0.0.1:8080 router.php بعد إعداد MySQL. هذا للتطوير المحلي وليس طريقة تشغيل الاستضافة.

## البيانات السابقة

إذا جهزت بالفعل نسخة MySQL السابقة بنفس الجداول والمالك الافتراضي ejaz-admin، يمكنك استخدام القاعدة نفسها؛ المثبت يضيف جدول محاولات الدخول ويحافظ على بيانات السير والصور والملفات الموجودة. أنشئ حساب المدير من المثبت للنسخة الجديدة.

أما بيانات Cloudflare D1 أو SQLite فلا تتحول إلى MySQL تلقائيًا. احتفظ بالنسخة القديمة ونسختها الاحتياطية أولًا، ولا تستورد ملف SQLite في phpMyAdmin على أنه MySQL. تظل ملفات R2 المنفصلة خارج قاعدة SQLite؛ يلزم نقلها كذلك إذا أردت استعادة الملفات الأصلية.

## تعديل الواجهة مستقبلًا

مجلد frontend-source يحتوي مصدر الواجهة للاطلاع والتطوير فقط، وهو محجوب عن الويب. ملفات التشغيل داخل assets جاهزة بالفعل، ولا تبنيها على Hostinger. تغيير منطق الخادم يتم في ملفات PHP داخل api وprivate. لتعديل JSX أو خوارزمية OCR يمكن لمطور بناء الأصول محليًا من frontend-source ثم رفع assets الناتجة؛ هذا لا يضيف Node.js إلى سيرفر الموقع.

## التحقق

نجحت مراجعة صياغة ملفات PHP واختبارات فعلية على PHP 8.3 وMariaDB متوافقة مع MySQL، دون تشغيل Node.js لخدمة الموقع:

- التثبيت وإنشاء الجداول وقفل المثبت، وتسجيل الدخول والخروج والجلسات وCSRF.
- منع رؤوس الهوية المزورة، وحماية الملفات والصور والنماذج المرفقة.
- حفظ السيرة وملفها وصورتها، منع التكرار، تحديثها، النسخ السابقة وتعارض الإصدار.
- تصدير SQL وJSON واستعادة SQL في قاعدة مستقلة ومقارنة بايتات الملف الأصلي.
- استخراج OCR وصور حفصة وبنغلاديش والفلبين وكينيا، وحفظ دفعة مع فشل ملف وإعادة محاولته، والحفظ الفردي لملف الصومال.
- السجلات والبحث وCSV وتبديل لغة النموذج والطباعة والتعديل.
- تشغيل التثبيت والدخول وOCR والصور والحفظ والسجلات من مجلد فرعي /ejaz أيضًا.

النص الممسوح منخفض الجودة قد يحتاج استكمالًا يدويًا. الاستخراج لا يضمن صحة المصدر أو هوية الصورة؛ المراجعة قبل الحفظ والرفع والقص اليدوي متاحة كما كانت. لم تُرفع النسخة على حساب Hostinger الخاص بك ضمن هذه الحزمة.

## تحديث الصور والتحميل
يستمر لودر بدء التشغيل حتى اكتمال تحميل الصفحة والخطوط ورسم الواجهة. مؤشر معالجة الملفات ثابت أسفل الشاشة حتى اكتمال العمل. يجري البحث المكبّر عن الوجوه الصغيرة في صور الجسم الكامل داخل السيرة قبل الرجوع إلى صورة الجواز، مع استبعاد نتائج الكشف منخفضة الثقة. اختُبر ملف كينيا MWANATUMU بصريًا للتأكد من اختيار صورة السيرة الملونة بدل صورة الجواز.

## إصلاح انقطاع MySQL أثناء حفظ الملفات على XAMPP
تُحفظ ملفات PDF وWord الأصلية داخل MySQL. يجب أن يسمح max_allowed_packet بحجم الملف مع هامش إضافي؛ يوصى بـ64M لدعم حد التطبيق 25MB. من لوحة XAMPP افتح MySQL ثم Config ثم my.ini، وعدّل القيمة الموجودة تحت [mysqld] إلى max_allowed_packet=64M. لا تستبدل ملف my.ini كله ولا تكرر المفتاح. أوقف MySQL وشغّله مجددًا. تحقق عبر phpMyAdmin: SHOW VARIABLES LIKE 'max_allowed_packet'; والناتج المطلوب 67108864. لا يتطلب ذلك إعادة إنشاء القاعدة. التحديث يفحص الحد قبل الكتابة ويعيد خطأ JSON واضحًا، ويتعامل مع فشل rollback دون إخفاء الخطأ الأصلي. لا يعيد محاولة الحفظ تلقائيًا إذا انقطع الاتصال وقت اعتماد العملية؛ راجع السجلات أولًا.

## عرض الصورة كاملة
تستخدم صورة PDF المضمّنة كاملة عند تطابقها مع الوجه المكتشف، وبالبكسلات الأصلية عندما تكون متاحة. عند تعذر فصل الصورة يكون القص أوسع ليشمل الرأس والكتفين وجزءًا من الجسم. يحافظ العرض على أبعاد الصورة دون قصّها لملء الإطار. جودة الملف الأصلي تظل هي الحد الأعلى للدقة.

## تحديث تنبيهات المراجعة
أضيفت مسافة داخلية حول تنبيه الخطأ في كارت المراجعة، مع ضبط المسافات للشاشات الصغيرة.

## صفحة الدخول الجديدة
تصميم عربي متجاوب بهوية إيجاز الأخضر والبرتقالي، حقول واضحة، زر إظهار/إخفاء كلمة المرور، وحالات انتظار وخطأ. لا يتطلب تغيير حساب المدير أو قاعدة البيانات.


## مراجعة استخراج PDF
تُراجع جميع الصفحات، وتُقرأ المهارات المؤشرة داخل الجداول والخبرة الخارجية بصورة مستقلة. أضيفت مراجعة مكبرة للعمر والطول والوزن واستكمال بيانات الجواز من الصفحات اللاحقة، مع التحقق من التواريخ وقراءة MRZ عند إمكان التحقق من أرقامه. التاريخ المستقبلي أو المتعارض يحتاج مراجعة ولا يُخمن.
يعرض كل سجل النص الكامل المستخرج للمراجعة، بما فيه بيانات لا تقابل حقلاً مستقلًا. جودة المسح وتعارض البيانات في المصدر قد يقتضيان تصحيحًا يدويًا؛ لا يضمن OCR قراءة كل ملف بنسبة 100%. أعد رفع الملفات السابقة لاستخراجها بالنسخة الجديدة. احتفظ بإعدادات الاتصال الحالية عند التحديث.


## القراءة المجانية متعددة المحاولات والتنبيه على الحقول
تُراجع كل صفحة ضوئيًا حتى عند توفر نص PDF، لاكتشاف الصفحات المختلطة التي تحتوي عنوانًا نصيًا وبيانات ممسوحة. تُستخدم القراءة الإضافية لملء الحقول المفقودة مع إبقاء الاختلافات للمراجعة. المعالجة أشمل وقد تستغرق وقتًا أطول حسب عدد الصفحات وجودة الملف. تُقارن قراءة الصورة الأصلية بقراءة نسخة محسّنة بالتباين الثنائي التلقائي، وتستمر مراجعة الأرقام والجواز المكبّرة. تحسين الصورة لا يخلق تفاصيل مفقودة، ولا تستخدم هذه الميزة خدمة مدفوعة أو API خارجيًا.
تظهر الحقول الناقصة والمتعارضة والمنخفضة الوضوح بلون تنبيه مع السبب، وتظهر بدائل القراءة وصفحاتها عند توفرها. غياب القيمة لا يعني أنها موجودة بالضرورة: قد تكون غير مذكورة في المصدر. صحّح الحقل أو اضغط تأكيد مراجعته بعد الرجوع للأصل. لا يتاح اعتماد الملف حتى مراجعة الحقول المعلّمة، والحفظ الفردي والجماعي يلتزمان بذلك. زر إعادة القراءة يعيد التحليل ويلغي تأكيدات المراجعة السابقة.
تُحفظ حالة مراجعة الحقول مع السجل دون تغيير مخطط قاعدة البيانات. الملفات القديمة لا تُحلل بأثر رجعي؛ أعد رفعها. اتفاق المحاولات ليس ضمان صحة، والتصاميم غير المعروفة والمسح التالف قد تنتج أخطاء غير مكتشفة.
